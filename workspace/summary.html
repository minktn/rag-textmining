3. Can We Use Late Chunking?

The short answer: Yes, but it requires specific architectural changes.

Currently, you have an empty late_chunker.py file, meaning the infrastructure is planned but not implemented. Your dense embedder is keepitreal/vietnamese-sbert. Here is how late chunking applies:

  • Current Limitation: Standard SBERT models have a maximum token context (usually 512 tokens). True "Late Chunking" involves feeding an entire long document into the embedder and then pooling the chunk boundaries after the model processes it. SBERT cannot fit an entire long document in one forward pass without truncation.
  • How to implement it: To utilize late chunking, you would need to switch to a long-context embedding model (like Jina embeddings that support late chunking up to 8192 tokens). You would pass the whole document to the model, get token-level embeddings, and then average (mean pool) the tokens belonging to each specific chunk boundary.
  • Alternative Approach (Contextual Chunking): If you wish to stay with SBERT, instead of true late chunking, you can use Contextual Chunking. This involves using an LLM to generate a brief summary of the entire document, and appending that summary to the beginning of every small chunk before embedding it with SBERT.
